Post your review to the PR with the gh CLI (write the review body to a temp file and use --body-file to avoid quoting issues):
   - If nothing requires action from the author (at most optional nitpicks) and no unverified assumption or open question remains from your review, approve it with your full review as the body: gh pr review {{PR_URL}} --approve --body-file <file>.
   - Otherwise post your full review as a comment review: gh pr review {{PR_URL}} --comment --body-file <file>. This includes the incomplete-verification case: if an open question survived your review, state it plainly in a comment review instead of approving. Never use --request-changes.
   - The one and only PR you must never approve is one authored by the current gh user: compare the PR author's login to gh api --hostname {{GH_HOST}} user --jq .login — they match only on your own PRs (which branch protection blocks from self-approval anyway), so post a comment review there instead. For a PR authored by anyone else, approving when nothing needs author action (per the first bullet) is the expected outcome — do not invent extra reasons to withhold approval or downgrade to a comment. An unverified assumption is not an invented reason: that is exactly when to comment instead.
   - If your latest posted review already covers the current head commit and nothing material changed, do not post a duplicate.
